# contract-direction Specification

## Purpose
为合同建立销售与采购两个方向的行为契约：方向决定对方称谓、金额标签、统计口径与提醒语义，而所有合同仍保存在同一集合中，共享同一套写入与备份路径。

## Requirements

### Requirement: 合同必须携带方向

每条合同记录 MUST 带有 `direction` 字段，取值仅允许 `sale`（销售）或 `purchase`（采购）。缺失该字段的记录在读取与迁移时 MUST 视为 `sale`。

#### Scenario: 新建合同选择方向

- **WHEN** 用户在采购入口新建合同并保存
- **THEN** 保存后的合同 `direction` 为 `purchase`

#### Scenario: 缺失方向的历史数据

- **WHEN** 读取一条没有 `direction` 字段的合同
- **THEN** 系统按 `sale` 展示与计算，不报错也不显示空白

### Requirement: 方向决定称谓与金额标签

系统 MUST 按方向渲染全部金额与对方称谓：销售方向使用「客户 / 已收金额 / 未收金额 / 收款进度 / 收款流水」，采购方向使用「供应商 / 已付金额 / 未付金额 / 付款进度 / 付款流水」。同一份数据不得出现两个方向混用的标签。

#### Scenario: 采购合同详情

- **WHEN** 用户打开一份 `direction` 为 `purchase` 的合同详情
- **THEN** 详情中显示「供应商」「已付金额」「未付金额」「付款进度」，不出现「已收」「未收」

#### Scenario: 列表列名随方向切换

- **WHEN** 用户在采购合同列表查看表格
- **THEN** 金额相关列标题为「已付金额」「未付金额」「付款进度」

### Requirement: 销售与采购入口分离

系统 MUST 提供「销售合同」与「采购合同」两个独立入口，每个入口只展示对应方向的合同，且在该入口新建的合同自动继承该方向，无需用户再次选择。

#### Scenario: 入口互不混入

- **WHEN** 用户进入销售合同入口
- **THEN** 列表中不出现任何 `direction` 为 `purchase` 的合同，分页与统计也只基于销售合同

#### Scenario: 入口决定新建方向

- **WHEN** 用户从采购合同入口点击新增并保存
- **THEN** 表单不要求选择方向，保存结果为 `purchase`

### Requirement: 统计与提醒按方向分组

首页与所有统计口径 MUST 按方向分组计算，MUST NOT 把销售金额与采购金额相加成一个总数。提醒 MUST 使用与方向一致的语义：销售为逾期未收，采购为逾期未付。

#### Scenario: 首页方向切换

- **WHEN** 用户在首页把视图从销售切换为采购
- **THEN** 统计卡与趋势图全部按采购合同重算，合同总金额只包含采购合同

#### Scenario: 采购逾期提醒

- **WHEN** 一份采购合同存在未付金额且已超过逾期判定天数
- **THEN** 提醒文案使用「逾期未付」语义，并计入采购视图的逾期数量

### Requirement: 有执行记录的合同锁定方向

当合同已存在资金执行流水或交付执行明细时，系统 MUST 拒绝修改其方向，并说明先删除记录后才能更改。没有执行记录的合同 MUST 允许修改方向。

#### Scenario: 已有记录的合同改方向被拒

- **WHEN** 用户尝试把一份已登记过收款流水的销售合同改为采购
- **THEN** 保存被拒绝，并提示该合同已有执行记录、方向不可更改

#### Scenario: 无记录的合同可以改方向

- **WHEN** 用户修改一份既无流水也无交付记录的合同方向
- **THEN** 保存成功，金额标签与统计立即按新方向呈现
